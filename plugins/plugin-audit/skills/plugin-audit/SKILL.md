# Plugin Audit

Claude Codeプラグイン（1個のプラグインディレクトリ、または `.claude-plugin/marketplace.json` を持つマーケットプレイス全体）を対象に、構造的な妥当性と品質を検証する。

## 手順

1. 対象パスを特定する（マーケットプレイスのルート、または単一プラグインのディレクトリ）。
2. 同梱の検証スクリプトを実行する:

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/audit_plugin.py" <path>
   ```

   機械可読な出力が必要なら `--json` を付ける。マーケットプレイスのルートを渡すと `marketplace.json` に列挙された、ローカル相対パス（`source` が `.` または `/` で始まるもの）を持つプラグインをすべて監査する。単一プラグインのディレクトリを渡すとそのプラグインだけを監査する。

3. スクリプトが検出するのは以下の機械的チェックのみ:
   - `plugin.json` / `hooks/hooks.json` / `.mcp.json` / `.lsp.json` のJSON構文エラー
   - `plugin.json` の必須フィールド（`name`）欠落、kebab-caseでない名前、未知のトップレベルフィールド
   - `.claude-plugin/` 直下に `plugin.json` 以外のファイル・ディレクトリが紛れ込んでいないか（公式ドキュメント上、コンポーネントディレクトリはプラグインルート直下でなければならない）
   - `SKILL.md` の `description` frontmatter欠落
   - コマンド・エージェント・スキル名の重複（同一プラグイン内で同名が複数定義されている、あるいは同じ識別子がスキルとコマンドの両方に存在し `/plugin:name` 名前空間が衝突している）
   - エージェントの `name`/`description` 欠落、未知のfrontmatterフィールド、`isolation` に `worktree` 以外の値
   - **エージェントに `hooks`・`mcpServers`・`permissionMode` が指定されている場合の検出** — これはプラグイン同梱エージェントではサポートされておらず、`claude plugin validate` はエラーにせず黙って無視するため見落としやすい
   - `SKILL.md`・コマンドの本文が `references/`・`scripts/`・`assets/` 配下のファイルを参照しているのに実体が存在しない（参照切れ）

   ERROR は動作に影響する不具合、WARN は品質上の懸念として報告する。

4. スクリプトでは検出できない、手動での確認が必要な観点を必ず追加でチェックする:
   - **意味的な重複・衝突**: 名前は異なっていても、複数プラグイン（あるいはこのリポジトリの `skills/` 一覧にある既存スキル）の `description` が同じ発火条件・同じ目的をカバーしていないか。両方インストールされたときにどちらが起動するか予測できない状態は、名前の衝突と同じくらい実害がある。
   - **発火条件の質**: `description` が具体的な発火語・使用場面を含んでいるか、それとも曖昧で自動起動が信頼できないか。
   - **`${CLAUDE_PLUGIN_ROOT}` の使用**: スクリプトやコマンドがプラグイン自身のファイルを参照する際、ハードコードされた絶対パスではなく `${CLAUDE_PLUGIN_ROOT}` を使っているか。
   - **marketplace.json と実ディレクトリの整合性**: `plugins/` 配下にあるのに `marketplace.json` に載っていないプラグイン、あるいはその逆がないか。
   - **バージョン管理の意図**: `version` を意図的に固定しているか（固定した場合、更新のたびに手動で上げる必要がある）、それとも意図的に省略してコミットSHA追従にしているか。

5. 結果をプラグインごとに要約する: コンポーネント数（skills/commands/agents）、ERROR一覧、WARN一覧、手動チェックで見つかった意味的な重複・衝突。ERRORが1件でもあれば「公開/インストール前に直すべき」ものとして明示する。
