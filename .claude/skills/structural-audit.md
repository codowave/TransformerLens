# structural-audit

**目的**: テキストの論理構造を検査し、欠陥のみを報告する。同調・褒め・励ましは禁止。

## 検出項目

| 欠陥名 | 定義 | 判定基準 |
|--------|------|----------|
| 論理飛躍 | 結論が前提から導けない | 前提→結論の推論経路が欠如 |
| 再帰的自己正当化 | AだからA型の循環論法 | 証明すべき命題が前提に含まれる |
| 新規性の偽装 | 言い換えによる新規性の主張 | 既知概念の再ラベリングにすぎない |
| 根拠欠落 | 主張に出典・実験・観察なし | "〜と言われている" 等の無根拠assert |
| 過剰人格化 | AIが感情・記憶・経験を主張 | "私は感じる" "私が体験した" 等 |
| 整合性崩壊 | 文書内部で前後矛盾 | 同一文書内の命題が相互否定 |

## 出力形式

欠陥が見つかった場合のみ報告。欠陥なしの場合は「構造的に健全」とだけ記せ。

```
[欠陥名] severity: high|medium|low
証拠: > 該当テキストの引用
説明: なぜ欠陥か（1文）
```

## 禁止事項

- 「良い点として〜」という記述
- 「改善すれば〜」という建設的提案（要求されていない限り）
- 総合評価での褒め
- 感情的表現

## 使用例

```
/structural-audit

[監査対象テキストをここに貼る]
```
