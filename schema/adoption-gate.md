# 昇格条件（Adoption Gate）

このファイルは `wiki/candidates/` → `wiki/verified/provisional/` → `wiki/verified/confirmed/` の
昇格条件を定義します。昇格条件は厳格に適用し、例外は設けません。

---

## ステージ定義

### wiki/candidates/
AIが生成した接続、または根拠が未検証の接続を置く場所です。  
候補段階では接続の真偽は問いません。可能性を記録する場所です。

**配置条件（全て満たすこと）**
- `templates/candidates-template.md` を使用して作成されていること
- 接続理由の類型が少なくとも1つ記入されていること
- 事実 / 仮説 / 比喩 / 未検証 の区分が記入されていること

---

### wiki/verified/provisional/
直接確認を経た接続を置く場所です。

**昇格条件（全て満たすこと）**

1. **AI外部直接確認が1件以上あること（必須・絶対条件）**  
   - 原語辞典・聖書本文・学術論文・現場観察などを、AI を介さずに人間が直接確認した記録があること。
   - 具体的には「確認来歴」欄に、確認者・確認日時・確認種別・資料または場所・確認内容を記入すること。

2. **candidates テンプレートの全欄が埋まっていること**

3. **以下のいずれもが昇格根拠になっていないこと**  
   - 比喩の美しさ・一貫性・深さ感
   - 複数AIの同意・AIの確信度
   - スウェーデンボルグ等の解釈者による言及のみ
   - AI対話ログのみ

---

### wiki/verified/confirmed/
複数条件を通過し、再検証でも矛盾が出ない接続を置く場所です。

**昇格条件（全て満たすこと）**

1. `provisional` の全条件を通過していること

2. **以下の5条件のうち複数を通過していること**  
   - 原語条件：ヘブライ語またはギリシャ語の語義・語根による支持
   - 本文条件：複数の聖書箇所における本文文脈による支持
   - 文脈条件：歴史的・文化的・文学的文脈による支持
   - 現実照合条件：現場観察・体験・実証による支持
   - 時間経過条件：時間をおいた再検証で矛盾が生じていない

3. **再検証ログ（日時・結果・矛盾の有無）が時系列で記録されていること**

4. **最新の再検証でも矛盾が出ていないこと**

---

## 採択禁止理由（これだけを根拠にしてはならない）

以下の項目は単独では `verified` 昇格の根拠になりません。  
補助資料として参照することは許可されますが、採択の決め手にはできません。

| 禁止根拠 | 理由 |
|---|---|
| 比喩の美しさ | 主観的であり検証不能 |
| 一貫性・深さ感 | 解釈の統合感は真偽の証拠にならない |
| 複数AIの同意 | AIは同じ訓練データに基づくため独立した確認にならない |
| AIの確信度 | 確信度は正確性の保証ではない |
| スウェーデンボルグ等の言及のみ | 解釈者の権威は独立した検証を代替しない |
| AI対話ログのみ | AI対話は候補生成の種であり確認の手段ではない |

## フィールド分離の原則

`fact-status`・`claim-type`・`connection-source` は互いに独立した軸です。混同すると辞典全体の一貫性が失われます。

| フィールド | 問い | 値の語彙 |
|---|---|---|
| `fact-status` | このファイルは今どの採択ステージか | `candidate` / `provisional` / `confirmed` |
| `claim-type` | この接続の主張の型は何か | `fact` / `hypothesis` / `metaphor` / `interpretation` / `application` / `mixed` |
| `connection-source` | この接続はどこから来たか | 接続由来8類型（日本語配列） |

**発生源と主張型は直交軸です。**  
発生源が何であるかは主張型を一意に決定しません。同じ発生源から複数の主張型が生まれえます。  
`connection-source: interpretation` のようなスカラー英語値は語彙の混入であり、lint ルール V-01 で検出されます。

---

## 典型パターン

`connection-source` と `claim-type` は独立して選びます。以下の例は、同じ発生源から異なる主張型が生まれること、および見かけ上「不一致」に見えるペアも正当であることを示します。

### パターン1：解釈者由来 × 仮説（"不一致"に見えるが正当）
```yaml
fact-status: candidate
claim-type: hypothesis
connection-source: [解釈者由来]
```
スウェーデンボルグの記述から着想を得たが、まだ仮説として扱っている候補。  
解釈者由来だからといって `claim-type: interpretation` にする必要はない。

### パターン2：原語由来 × 仮説
```yaml
fact-status: provisional
claim-type: hypothesis
connection-source: [原語由来]
```
原語語義から着想した接続で、AI外部直接確認を1件通過したもの。  
原語確認が済んでも、接続の解釈に不確かさが残れば `hypothesis` のままで正当。

### パターン3：本文文脈由来 × 比喩（発生源と型が直交する例）
```yaml
fact-status: candidate
claim-type: metaphor
connection-source: [本文文脈由来]
```
本文の文脈から見いだされた比喩的接続。  
「本文から来た」ことと「比喩的主張である」ことは矛盾しない。

### パターン4：原語由来 × 事実（確定接続の典型）
```yaml
fact-status: confirmed
claim-type: fact
connection-source: [原語由来]
```
原語を直接確認し、複数条件と再検証を通過した確定接続。  
`claim-type: fact` にするには発生源にかかわらず、十分な確認の積み上げが必要。

## ダウングレード

昇格後に矛盾が発見された場合は、一段階下のステージに戻すことができます。  
その場合は再検証ログに日時・発見した矛盾・ダウングレード理由を記録してください。
